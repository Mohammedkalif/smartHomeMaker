# Deploy Smart Homemaker

This project is set up for separate frontend and backend deployment on Render:

- **`smart-homemaker-api`**: FastAPI web service
- **`smart-homemaker-web`**: React static site served through Render's CDN
- **`smart-homemaker-db`**: managed PostgreSQL database

The backend is explicitly pinned to Python 3.12 in both `render.yaml` and
`backend/.python-version`. This prevents Render's newer default Python runtime
from attempting to build the pinned `pydantic-core` dependency from source.

The database is included because SQLite files on a web service are not durable across deployments. Passwords are stored as PBKDF2 hashes, and the session signing secret is generated by Render.

## One-time preparation

1. Put the project in a private GitHub repository. Do not commit `backend/.env`.
2. If the Groq key shown in any previous README or commit is real, revoke it in Groq and create a new one before deployment.
3. Sign in at [Render](https://dashboard.render.com/), select **New > Blueprint**, and connect the GitHub repository. Render detects `render.yaml` at the repository root.

## Create the services

During Blueprint setup, Render prompts for these variables:

- `GROQ_API_KEY`: paste your newly created Groq API key.
- `FRONTEND_ORIGIN`: temporarily enter `https://placeholder.invalid`.
- `VITE_API_BASE`: temporarily enter `https://placeholder.invalid`.

Approve the Blueprint. It deploys the API, frontend and Postgres database as independent Render resources. Wait until both services show **Live**.

## Connect the two public services

1. Open the API service and copy its public URL, for example `https://smart-homemaker-api.onrender.com`.
2. In the **static site** environment variables, set `VITE_API_BASE` to that API URL, with no trailing slash. Save it and manually redeploy the static site.
3. Open the static site and copy its public URL.
4. In the **API** environment variables, set `FRONTEND_ORIGIN` to that static-site URL, with no trailing slash. Save it and redeploy the API.
5. Visit the static site, create an account with a name and password, and confirm your name appears on the dashboard and Profile page.

For a custom domain, add it to the static site first, then replace `FRONTEND_ORIGIN` with that exact HTTPS domain and redeploy the API.

## Verify

- API: open `https://YOUR-API/api/health` and expect `{"status":"ok"}`.
- Web: sign up, refresh a page such as `/profile`, and ensure it loads instead of a 404.
- Security: confirm an unauthenticated request to `/api/profile` returns 401.

Render's static-site rewrite is included so React Router routes such as `/profile` work after a browser refresh. The Blueprint keeps secrets out of source control and links the API to the managed Postgres connection string automatically.
